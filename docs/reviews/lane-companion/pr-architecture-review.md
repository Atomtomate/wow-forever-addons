### 1. The game-folder writers import `config`, the package that holds the key and the link state, to borrow its file writer
- **file:line**: `companion/internal/dataaddon/dataaddon.go:16`, `:91`, `:114`, `:137` and `companion/internal/install/install.go:17`, `:219` (plus `companion/internal/app/setup.go:286` for the program copy). Their only use of `config` is `config.WriteFileAtomic`.
- **The crossing**: `dataaddon` → `config` and `install` → `config`. The call resolves to `companion/internal/config/config.go:60`. That helper creates every missing parent folder with mode `0o700` (`:61`), the private-folder policy of the config directory. So the `ForeverFriends` and `ForeverFriendsData` folders and the program folder inherit a permission chosen for the folder that holds `device.key`.
- **The rule**: `config` is "what the companion remembers between runs, in one folder it is given" (`config.go:1`). `docs/CONTRACT.md` §5 separates what the companion writes inside the game folder from what it keeps outside it. The import graph now runs from the inside writers to the outside store. Any change to how the config folder is written (mode, fsync, temp name) changes how the addon is installed. The next writer will reach for `config` too, because that is where the helper is.
- **The fix**: Move `WriteFileAtomic` into a package of its own under `companion/internal/` that `config`, `dataaddon`, `install` and `app` import. It should take the folder mode from the caller. This adds a package.

### 2. `savedvars` checks the §1 file's `version` against `wire.Version`, the §3 wire version
- **file:line**: `companion/internal/savedvars/read.go:113`–`114`
- **The crossing**: `savedvars` → `wire.Version` (`companion/internal/wire/wire.go:13`). The `wire` package says it holds "the JSON shapes and numeric limits of docs/CONTRACT.md §3" (`wire.go:1`). The §2 file has its own version, written as a literal in `dataaddon.go:51`. The §1 file's version is the only one obtained from another format's constant.
- **The rule**: `docs/CONTRACT.md` versions each format separately: a breaking change "bumps the version in that section, and the reader refuses a version it does not know". The question "which SavedVariables version do I read?" is answered by asking which JSON version the companion sends. Bumping `v` to 2 for a sync change would make every SavedVariables file still at `version = 1` unreadable.
- **The fix**: Give `savedvars` its own constant for the §1 version and compare against that. This adds one constant.

### 3. `install.IsLink` hard-codes Windows' answer to "do paths ignore case", which `platform` owns
- **file:line**: `companion/internal/install/install.go:106`–`119`. The `strings.EqualFold` is at `:119`, and the `os.ModeIrregular` check for Windows junctions is at `:111`.
- **The crossing**: `install` answers the question itself. The owner is `platform.CaseFoldPaths` (`platform_windows.go:70` true, `platform_other.go:28` false). `app` carries it as `Env.P.CaseFold` into `gamefind.Running(…, foldCase)` (`gamefind.go:50`) and into `app.samePath` (`app.go:155`). `install.Install` and `install.Remove` are given neither the fact nor a comparison, so the package holds a second, unconditional answer.
- **The rule**: "Code for one operating system sits in `_windows.go` / `_other.go` files behind one small function each" (`.claude/agents.local.md`). `IsLink`'s doc comment calls it a Windows test, but it lives in a shared file. The next comparison of paths now has two homes to copy from.
- **The fix**: Have `Install` and `Remove` take the case rule from the caller, as `gamefind.Running` does, and pass it to `IsLink`. `app` then passes `Env.P.CaseFold`. This adds a parameter.

### 4. The contract's "never follows a redirect" lives wherever the caller builds the `*http.Client`, not in `hubapi`
- **file:line**: `companion/internal/hubapi/hubapi.go:64`–`71` and `:121`; `companion/internal/app/app.go:95`–`97`
- **The crossing**: `hubapi.Client.do` sends through whatever `HTTP` it is handed (`:121`). The guard sits in `NewHTTPClient`'s `CheckRedirect`, and in production it is applied only because `app.Main` fills a nil `Env.HTTP` with that constructor. `DefaultEnv` (`companion/internal/app/env.go:13`), the declared home of "the real thing", does not set it. So the rule depends on how `app` was wired, and the package also defaults to the real network when its caller passes none.
- **The rule**: `hubapi` calls itself "the only code that sends anything to the hub" (`hubapi.go:1`). §3 makes the redirect rule what keeps a signed path equal to the path the hub sees. A rule that guards the signature belongs inside the sender, not in a constructor a caller may skip. The overlay adds that packages reach the network "only through what the caller passes in". A nil-default inside `Main` is the package reaching for the network on its own.
- **The fix**: Have `do` enforce the rule on any client, for example on a shallow copy with `CheckRedirect` set. Then move the production client into `DefaultEnv`. This adds a few lines to `hubapi`.

### 5. `app` re-derives file layouts that `dataaddon` and `applog` own
- **file:line**: `companion/internal/app/run.go:78` and `companion/internal/app/setup.go:213` (`"Data.lua"`). `companion/internal/app/remove.go:97` (`config.LogFile + ".1"`).
- **The crossing**: The member list's file name is a literal inside `dataaddon.Write`/`EnsureEmpty` (`dataaddon.go:102`, `:133`). `app` restates it twice to answer two questions: whether a list exists (the §3.3 `roster_etag` condition) and whether the folder is new (whether a restart is needed). The log's rotated name is `applog`'s (`applog.go:32`), and `remove` restates it.
- **The rule**: A module needing a fact should get it from whatever owns it. `dataaddon` declares itself the owner of the folder (`dataaddon.go:20`). Renaming its file, or changing `applog`'s rotation, would silently break `run`'s etag condition or leave files behind after `remove`.
- **The fix**: Add `dataaddon` and `applog` functions that answer those questions (whether a list is present; which files the log may leave), and have `app` call them. This adds two small functions.

### 6. The §3.1 `device_name` rule and its 40-character limit live in the command layer
- **file:line**: `companion/internal/app/app.go:43` (`deviceNameLimit = 40`) and `:164`–`178` (`cleanDeviceName`). It is called at `companion/internal/app/setup.go:162`, `:165`.
- **The crossing**: The name reaches the wire through `linkflow.Start` → `hubapi.StartLink` → `wire.LinkRequest.DeviceName`. Neither of those applies or knows the rule. Its only home is `app`, next to UI constants such as `stopWait` and `logMaxBytes`.
- **The rule**: `wire` is the declared single home of §3's limits, "so that the package which sends ... cannot disagree" (`wire.go:1`–`3`). `docs/CONTRACT.md` §3.1 sets the 40 and the cleaning. Any second caller of `linkflow.Start` sends an uncleaned name and stores it in `config.json`.
- **The fix**: Move the limit into `wire` and apply the cleaning in `linkflow.Start`, the owner of §3.1. `app` keeps calling it only for the prompt's default. The code moves rather than grows, plus one exported name.

### 7. `instance` splits by OS as `_unix.go`/`_windows.go`, not the `_windows.go`/`_other.go` pair, and duplicates code that is not OS-specific
- **file:line**: `companion/internal/instance/lock_unix.go:1` (`//go:build unix`) and `:28`; `companion/internal/instance/lock_windows.go:31`
- **The crossing**: `Release` is identical in both OS files. `platform` uses `_other.go` with `!windows` (`platform_other.go:1`), so the companion now has two conventions for the same split. Under `unix`, a target that is neither (`js`, `wasip1`, `plan9`) has no `TryAcquire`.
- **The rule**: "Code for one operating system sits in `_windows.go` / `_other.go` files behind one small function each" (`.claude/agents.local.md`). Only `TryAcquire` differs by OS.
- **The fix**: Rename to `lock_other.go` with `//go:build !windows` and move `Release` into `instance.go`. The code does not grow.
